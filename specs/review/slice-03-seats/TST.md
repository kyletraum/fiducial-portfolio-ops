## Axis 2 — scope, buildability, teaching value

**Scope.** The slice is buildable as tests at every layer the repository already has, with one
honest subtraction: the published stack (DoD 3's second half, DoD 6's published CSP) stays a
hand step, as it was in slices 01 and 02, and the slice should say so rather than let "the
E2E" imply otherwise. The DoD items that need rewording to be judgeable are 2 (static files,
both environments) and 4 (what a browser can show once layer 2 refuses first). The rest have
oracles in reach of fixtures that exist.

**Buildability.** The cost that is easy to underestimate is the repair of the existing suites:
27 methods red at once, then red again for tokens. Done as two shared helpers and a setup-code
configuration value, it is a day; done test by test, it is the slice. The new auth tests belong
in `tests/Integration` so the time-zone jobs and the coverage layout need no CI change, and
one shared `AuthFixture` keeps the Testcontainers bill flat.

**Teaching value, for the gate's techniques limb.** Three test techniques this slice would
teach that slices 01 and 02 did not, each demonstrable in a commit: (1) a behavioural
"every mapped endpoint" test over `EndpointDataSource` that a new anonymous endpoint fails;
(2) a browser test that carries a real session into an attack and names the layer that
refused, with the cookie proven present; (3) a canary-based "nothing secret in the captured
output" test over logs, traces and error bodies at `Trace`, with a non-empty guard. The hook
test (git in a temp repository, with the clean twin) is a fourth, smaller one. The habit the
repository already has, "seen failing once", is what keeps each of these from passing while
false, and every finding above names where that one red run belongs.
